## 1. Basic Idea

In parallel scientific computing, high-performance algorithms follow the divide-and-conquer strategy: a massive dataset (such as an image to process, a matrix to decompose, or a physical mesh to simulate) is loaded or generated by a coordinator node and must be partitioned into **distinct, non-overlapping sub-arrays** distributed across worker processes.

While `MPI_Bcast` transmits an **identical copy** of an entire buffer to all processes, **`MPI_Scatter`** distributes **different, disjoint slices** of a single array located at the Root process across all cooperating ranks in the communicator.

If the Root process holds an array of $K = P \times S$ elements:
- Process 0 receives elements $[0 \dots S-1]$.
- Process 1 receives elements $[S \dots 2S-1]$.
- Process 2 receives elements $[2S \dots 3S-1]$.
- Process $r$ receives elements $[r \cdot S \dots (r+1) \cdot S - 1]$.

```
+-----------------------------------------------------------------------------------------+
|                              The MPI_Scatter Data Partitioning                          |
+-----------------------------------------------------------------------------------------+
| ROOT PROCESS (Rank 0) BUFFER:                                                           |
|   Index:  [ 0 | 1 ]   [ 2 | 3 ]   [ 4 | 5 ]   [ 6 | 7 ]  (Total = 8 elements)           |
|           +-------+   +-------+   +-------+   +-------+                                 |
|           Block 0     Block 1     Block 2     Block 3                                   |
|              |           |           |           |                                      |
|              v           v           v           v                                      |
|            Rank 0      Rank 1      Rank 2      Rank 3                                   |
|                                                                                         |
| AFTER SCATTER (recvcount = 2 per rank):                                                 |
|   Rank 0 Recv Buffer: [ 0 | 1 ]                                                         |
|   Rank 1 Recv Buffer: [ 2 | 3 ]                                                         |
|   Rank 2 Recv Buffer: [ 4 | 5 ]                                                         |
|   Rank 3 Recv Buffer: [ 6 | 7 ]                                                         |
+-----------------------------------------------------------------------------------------+
```

## 2. Why We Need It

### 1. Distinct Data Partitioning vs. Redundant Replication
In big-data analytics and HPC simulations, storing the entire global dataset in physical RAM on every node is impossible:
- A $100\text{ GB}$ satellite climate dataset cannot fit into the $16\text{ GB}$ local memory of a standard compute node.
- Broadcasting the $100\text{ GB}$ array via `MPI_Bcast` would exhaust node memory and crash the cluster with out-of-memory (`ENOMEM`) errors.
- `MPI_Scatter` solves this by delivering only the local $100\text{ GB} / P$ chunk to each node, enabling massive aggregate dataset processing across distributed cluster memory.

### 2. Eliminating $\mathcal{O}(P)$ Scatter Loops
Implementing a scatter manually using a loop of `MPI_Send` calls on the Root rank forces the root's network link to serialize $P-1$ individual transfers. `MPI_Scatter` utilizes tree-based distribution topologies, reducing network transfer time from linear scaling $\mathcal{O}(P)$ to logarithmic scaling $\mathcal{O}(\log P)$.

### 3. Vector Scatter (`MPI_Scatterv`) for Irregular Domains
When the problem size $N$ is not an exact integer multiple of process count $P$ ($N \pmod P \neq 0$), uniform chunking is impossible. MPI provides **`MPI_Scatterv`** (Vector Scatter), allowing the root to specify distinct slice lengths (`sendcounts[]`) and memory offset displacements (`displs[]`) for each individual rank.

## 3. How It Works

### The Memory Mechanics of `MPI_Scatter`

```
Root Process Memory Space (Rank == root):
  sendbuf ---> [ Slice 0 | Slice 1 | Slice 2 | ... | Slice P-1 ]
                    |         |         |                |
                    |         +---------+----------------+----> Traverses Interconnect
                    v                                           to Remote Nodes
  recvbuf ---> [ Slice 0 ]  (Root receives its own designated slice in local memory)

Non-Root Process Memory Space (Rank != root):
  sendbuf ---> Ignored (Can be NULL)
  recvbuf ---> [ Local Slice ]  <=== Incoming network data written here
```

- On the **Root rank**: The sending buffer `sendbuf` must contain at least $P \times \text{sendcount}$ contiguous elements.
- On **Non-Root ranks**: The arguments `sendbuf`, `sendcount`, and `sendtype` are ignored by the runtime (passing `NULL` is standard practice).
- On **All ranks** (including Root): `recvbuf` must point to allocated memory capable of holding `recvcount` elements.

---

### The Paramount `sendcount` vs. `recvcount` Semantic Trap

The single most common bug encountered by university students in MPI exams and lab evaluations is misunderstanding the `sendcount` parameter:

> [!WARNING]
> **The `sendcount` Parameter Rule:**
> In `MPI_Scatter`, **`sendcount` is the number of elements sent to EACH individual process**, NOT the total size of the array!
> 
> If Rank 0 has an array of $1{,}000$ integers and scatters them equally across $4$ processes, the call must specify:
> ```c
> /* CORRECT: 1000 / 4 = 250 elements sent to each rank */
> MPI_Scatter(big_array, 250, MPI_INT, local_array, 250, MPI_INT, 0, MPI_COMM_WORLD);
> ```
> Specifying `sendcount = 1000` tells MPI to send 1,000 integers to *each* of the 4 processes, reading $4{,}000$ integers from `big_array`. This reads 3,000 integers out-of-bounds, triggering an immediate **Segmentation Fault (`SIGSEGV`)** or memory corruption!

In standard uniform `MPI_Scatter`, `sendcount` and `recvcount` must be **strictly equal**:
$$\text{sendcount} = \text{recvcount} = \frac{N_{\text{total}}}{P}$$

## 4. Important Mechanisms and Functions

### 1. The `MPI_Scatter` Function Signature

```c
#include <mpi.h>

int MPI_Scatter(const void *sendbuf, int sendcount, MPI_Datatype sendtype,
                void *recvbuf, int recvcount, MPI_Datatype recvtype,
                int root, MPI_Comm comm);
```

- **`sendbuf`:** Pointer to source array on Root (ignored on non-root).
- **`sendcount`:** Number of elements sent to **each** process.
- **`sendtype`:** Datatype of elements in `sendbuf`.
- **`recvbuf`:** Pointer to local receiving array on all processes.
- **`recvcount`:** Number of elements received by the calling process.
- **`recvtype`:** Datatype of elements in `recvbuf`.
- **`root`:** Rank of the distributing process.
- **`comm`:** Communicator handle.

---

### 2. In-Place Reception: `MPI_IN_PLACE`

On the Root process, if the Root's computational data is already located in the first slice of `sendbuf`, passing a separate `recvbuf` wastes memory. The Root can pass **`MPI_IN_PLACE`** as its `recvbuf`:

```c
if (rank == root) {
    MPI_Scatter(array, count, MPI_INT, MPI_IN_PLACE, count, MPI_INT, root, comm);
} else {
    MPI_Scatter(NULL, 0, MPI_DATATYPE_NULL, local_buf, count, MPI_INT, root, comm);
}
```
When `MPI_IN_PLACE` is used, the root retains its own portion directly in `sendbuf` without copying.

---

### 3. Handling Uneven Slices: `MPI_Scatterv` (Vector Scatter)

When total items $N$ does not divide evenly by $P$ ($N \pmod P \neq 0$):

```c
int MPI_Scatterv(const void *sendbuf, const int sendcounts[], const int displs[],
                 MPI_Datatype sendtype, void *recvbuf, int recvcount,
                 MPI_Datatype recvtype, int root, MPI_Comm comm);
```

- **`sendcounts[]`:** Array of size $P$ where `sendcounts[r]` specifies how many elements to send to Rank $r$.
- **`displs[]`:** Array of size $P$ where `displs[r]` specifies the memory offset (in element units) from `sendbuf` where Rank $r$'s data begins.

```
Array Size = 10 elements | Processes P = 3
  sendcounts = [ 4, 3, 3 ]
  displs     = [ 0, 4, 7 ]
  ===> Rank 0 gets 4 elements starting at index 0 [0..3]
  ===> Rank 1 gets 3 elements starting at index 4 [4..6]
  ===> Rank 2 gets 3 elements starting at index 7 [7..9]
```

## 5. Compilable C Code Examples

### Example 1: Parallel Vector Normalization using `MPI_Scatter`
This complete program demonstrates Rank 0 reading/generating a large numerical vector, scattering distinct equal chunks across 4 worker processes, having each worker process compute the square root of each element locally, and validating the results.

```c
/*
 * File: mpi_scatter_demo.c
 * Compilation:
 *   mpicc -O2 mpi_scatter_demo.c -o mpi_scatter_demo -lm
 *
 * Execution:
 *   mpirun -np 4 ./mpi_scatter_demo
 */

#include <mpi.h>
#include <stdio.h>
#include <stdlib.h>
#include <math.h>

#define TOTAL_ELEMENTS 16

int main(int argc, char** argv) {
    int rank, size;
    MPI_Init(&argc, &argv);
    MPI_Comm_rank(MPI_COMM_WORLD, &rank);
    MPI_Comm_size(MPI_COMM_WORLD, &size);

    /* Enforce even divisibility for basic MPI_Scatter */
    if (TOTAL_ELEMENTS % size != 0) {
        if (rank == 0) {
            fprintf(stderr, "Error: TOTAL_ELEMENTS (%d) must divide evenly by process count (%d)\n",
                    TOTAL_ELEMENTS, size);
        }
        MPI_Abort(MPI_COMM_WORLD, EXIT_FAILURE);
    }

    int elements_per_rank = TOTAL_ELEMENTS / size;
    double* global_array = NULL;

    /* Allocate global data ONLY on Root (Rank 0) */
    if (rank == 0) {
        global_array = (double*)malloc(TOTAL_ELEMENTS * sizeof(double));
        printf("=================================================================\n");
        printf("  MPI_Scatter: PARALLEL VECTOR NORMALIZATION                     \n");
        printf("  Total Array Size: %d | Processes: %d | Elements/Rank: %d       \n",
               TOTAL_ELEMENTS, size, elements_per_rank);
        printf("=================================================================\n\n");

        printf("[Root Rank 0] Generating Global Dataset:\n[ ");
        for (int i = 0; i < TOTAL_ELEMENTS; ++i) {
            global_array[i] = (double)((i + 1) * (i + 1)); /* Perfect squares: 1, 4, 9, 16... */
            printf("%.0f ", global_array[i]);
        }
        printf("]\n\n");
    }

    /* Allocate local receiving array on EVERY rank */
    double* local_chunk = (double*)malloc(elements_per_rank * sizeof(double));

    /* =========================================================================
     * DISTRIBUTE DATA USING MPI_Scatter
     * Notice: sendcount is elements_per_rank (4), NOT TOTAL_ELEMENTS (16)!
     * ========================================================================= */
    MPI_Scatter(
        global_array, elements_per_rank, MPI_DOUBLE, /* Send args (Valid on Root) */
        local_chunk, elements_per_rank, MPI_DOUBLE,  /* Recv args (Valid on All)  */
        0 /* root */, MPI_COMM_WORLD
    );

    /* Print received slice */
    printf("  [Rank %d] Received Local Chunk: [ ", rank);
    for (int i = 0; i < elements_per_rank; ++i) {
        printf("%.0f ", local_chunk[i]);
    }
    printf("]\n");

    /* Compute square roots in parallel on private memory */
    for (int i = 0; i < elements_per_rank; ++i) {
        local_chunk[i] = sqrt(local_chunk[i]);
    }

    printf("  [Rank %d] Computed Square Roots : [ ", rank);
    for (int i = 0; i < elements_per_rank; ++i) {
        printf("%.1f ", local_chunk[i]);
    }
    printf("]\n");

    MPI_Barrier(MPI_COMM_WORLD);

    if (rank == 0) {
        printf("\n=================================================================\n");
        printf("Data successfully partitioned and computed in parallel!\n");
        free(global_array);
    }

    free(local_chunk);
    MPI_Finalize();
    return EXIT_SUCCESS;
}
```

```
--- Expected Output (Running with 4 Processes) ---
=================================================================
  MPI_Scatter: PARALLEL VECTOR NORMALIZATION                     
  Total Array Size: 16 | Processes: 4 | Elements/Rank: 4       
=================================================================

[Root Rank 0] Generating Global Dataset:
[ 1 4 9 16 25 36 49 64 81 100 121 144 169 196 225 256 ]

  [Rank 0] Received Local Chunk: [ 1 4 9 16 ]
  [Rank 1] Received Local Chunk: [ 25 36 49 64 ]
  [Rank 2] Received Local Chunk: [ 81 100 121 144 ]
  [Rank 3] Received Local Chunk: [ 169 196 225 256 ]
  [Rank 0] Computed Square Roots : [ 1.0 2.0 3.0 4.0 ]
```

### Example 2: Uneven Domain Partitioning with `MPI_Scatterv`
This example demonstrates scattering $N = 10$ integers across $P = 3$ processes. Because $10$ cannot divide evenly by $3$, `MPI_Scatterv` distributes chunks of sizes $4, 3, 3$ with precise memory displacements.

```c
/*
 * File: mpi_scatterv_uneven.c
 * Compilation:
 *   mpicc -O2 mpi_scatterv_uneven.c -o mpi_scatterv_uneven
 *
 * Execution:
 *   mpirun -np 3 ./mpi_scatterv_uneven
 */

#include <mpi.h>
#include <stdio.h>
#include <stdlib.h>

#define TOTAL_ITEMS 10

int main(int argc, char** argv) {
    int rank, size;
    MPI_Init(&argc, &argv);
    MPI_Comm_rank(MPI_COMM_WORLD, &rank);
    MPI_Comm_size(MPI_COMM_WORLD, &size);

    int* global_data = NULL;
    int* sendcounts  = (int*)malloc(size * sizeof(int));
    int* displs      = (int*)malloc(size * sizeof(int));

    /* Calculate equitable partitioning: N / P with remainder R */
    int base_count = TOTAL_ITEMS / size;
    int remainder  = TOTAL_ITEMS % size;
    int offset = 0;

    for (int r = 0; r < size; ++r) {
        sendcounts[r] = (r < remainder) ? (base_count + 1) : base_count;
        displs[r]     = offset;
        offset        += sendcounts[r];
    }

    if (rank == 0) {
        global_data = (int*)malloc(TOTAL_ITEMS * sizeof(int));
        printf("=== MPI_Scatterv: Uneven Partitioning (N = %d, P = %d) ===\n", TOTAL_ITEMS, size);
        for (int i = 0; i < TOTAL_ITEMS; ++i) {
            global_data[i] = (i + 1) * 10;
        }

        printf("Calculated Scatter Plan:\n");
        for (int r = 0; r < size; ++r) {
            printf("  Rank %d: %d elements starting at displacement %d\n",
                   r, sendcounts[r], displs[r]);
        }
        printf("\n");
    }

    /* Allocate local receiving buffer matching this rank's specific quota */
    int local_count = sendcounts[rank];
    int* local_data = (int*)malloc(local_count * sizeof(int));

    /* Execute Vector Scatter */
    MPI_Scatterv(
        global_data, sendcounts, displs, MPI_INT, /* Send args (Root) */
        local_data, local_count, MPI_INT,        /* Recv args (All)  */
        0, MPI_COMM_WORLD
    );

    printf("[Rank %d] Received %d elements: [ ", rank, local_count);
    for (int i = 0; i < local_count; ++i) {
        printf("%d ", local_data[i]);
    }
    printf("]\n");

    MPI_Barrier(MPI_COMM_WORLD);

    if (rank == 0) free(global_data);
    free(sendcounts);
    free(displs);
    free(local_data);

    MPI_Finalize();
    return EXIT_SUCCESS;
}
```

```
--- Expected Output (Running with 3 Processes) ---
=== MPI_Scatterv: Uneven Partitioning (N = 10, P = 3) ===
Calculated Scatter Plan:
  Rank 0: 4 elements starting at displacement 0
  Rank 1: 3 elements starting at displacement 4
  Rank 2: 3 elements starting at displacement 7

[Rank 0] Received 4 elements: [ 10 20 30 40 ]
[Rank 1] Received 3 elements: [ 50 60 70 ]
[Rank 2] Received 3 elements: [ 80 90 100 ]
```

## 6. Mathematical Formulations & Bandwidth Scaling

### Transmission Time Comparison: `MPI_Bcast` vs `MPI_Scatter`

Let $N_{\text{total}}$ be the total elements in the global array, and $m = N_{\text{total}} \cdot \text{sizeof(type)}$ be total bytes.

#### 1. In `MPI_Bcast`:
Every process receives the **entire** dataset of size $m$:

$$\text{Total Data Transferred Across Fabric} = (P - 1) \cdot m$$

#### 2. In `MPI_Scatter`:
Each process receives only an $S = \frac{1}{P}$ slice of size $\frac{m}{P}$:

$$\text{Total Data Transferred Across Fabric} = \left( \frac{P - 1}{P} \right) \cdot m \approx m$$

Notice the massive reduction in total network bytes:

$$\frac{\text{Bytes Transferred in Scatter}}{\text{Bytes Transferred in Bcast}} = \frac{m}{(P - 1) \cdot m} = \frac{1}{P - 1}$$

On 1,000 cluster nodes, `MPI_Scatter` moves **$1{,}000\times$ less data** across the network switches than `MPI_Bcast`, preventing network fabric congestion.

## 8. Standard Exam Definitions

> [!IMPORTANT]
> **Data Scatter (`MPI_Scatter`):** A one-to-all collective communication routine where a designated root process partitions a contiguous array into $P$ equal segments and distributes segment $r$ exclusively to process rank $r$ across the communicator.
>
> **`sendcount` in `MPI_Scatter`:** The number of data elements dispatched to **each individual process**, mathematically equal to $\frac{\text{Total Array Elements}}{P}$, and **not** the global array length.
>
> **Vector Scatter (`MPI_Scatterv`):** An extended collective scatter function allowing the root process to distribute unequal and non-contiguous segments of data to different ranks using arrays of element counts (`sendcounts[]`) and memory displacements (`displs[]`).
>
> **In-Place Collective (`MPI_IN_PLACE`):** A special memory optimization pointer passed as `recvbuf` on the root process indicating that its received slice already resides in the root's `sendbuf`, eliminating redundant buffer allocation and memory copying.

## 9. Comparison Tables

### `MPI_Bcast` vs `MPI_Scatter` vs `MPI_Scatterv`

| Dimension | `MPI_Bcast` | `MPI_Scatter` | `MPI_Scatterv` |
| :--- | :--- | :--- | :--- |
| **Data Pattern** | **Identical Copy** to all | **Different Equal Slices** to each | **Different Variable Slices** to each |
| **Total Elements at Root** | $S$ | $P \times S$ | $\sum_{r=0}^{P-1} \text{sendcounts}[r]$ |
| **Received per Rank** | $S$ elements | $S$ elements | `sendcounts[rank]` elements |
| **Handles Remainder?** | Not applicable | **No** (Must divide evenly) | **Yes** (Via displacement array) |
| **Memory Footprint** | Replicated on all nodes | Partitioned across nodes | Partitioned across nodes |

## 10. Solved Problems / Analytical Exercises

### Problem 1: The Out-of-Bounds `sendcount` Segmentation Fault
**Question:** An engineer writes the following code to distribute an array of $1{,}000$ integers across $4$ processes. When run with `mpirun -np 4`, the application crashes with `Segmentation fault (core dumped)`. Explain why.

```c
int data[1000];
int local[250];

/* Crash occurs here */
MPI_Scatter(data, 1000, MPI_INT, local, 250, MPI_INT, 0, MPI_COMM_WORLD);
```

**Solution:**
- **The Defect:** The engineer set `sendcount = 1000`.
- Under the MPI specification, `sendcount` represents the elements sent to **each** process.
- Specifying `sendcount = 1000` directs the MPI library to send $1{,}000$ integers to Rank 0, $1{,}000$ integers to Rank 1, $1{,}000$ integers to Rank 2, and $1{,}000$ integers to Rank 3.
- The root process attempts to read a total of:
$$4 \times 1{,}000 = 4{,}000\text{ integers} = 16{,}000\text{ bytes}$$
- Because `data` is allocated with only $1{,}000$ integers ($4{,}000$ bytes), MPI attempts to read $12{,}000$ bytes beyond the allocated stack/heap boundary into unmapped virtual memory, triggering a hardware MMU fault and instant **Segmentation Fault (`SIGSEGV`)**.
- **The Fix:** Change `sendcount` to `250` (or `1000 / size`).

### Problem 2: Constructing Displacements for `MPI_Scatterv`
**Question:** A dataset of $N = 14$ items is scattered across $P = 4$ ranks. Construct the exact `sendcounts[]` and `displs[]` arrays using the standard equitable remainder balancing algorithm.

**Solution:**
- Base chunk = $\lfloor 14 / 4 \rfloor = 3$.
- Remainder = $14 \pmod 4 = 2$.
- The first $2$ ranks receive $3 + 1 = 4$ items. The remaining $2$ ranks receive $3$ items.

| Rank ($r$) | `sendcounts[r]` | Calculation of Displacement (`displs[r]`) | `displs[r]` | Elements Assigned |
| :---: | :---: | :--- | :---: | :--- |
| **0** | 4 | Offset = 0 | **0** | Items $[0, 1, 2, 3]$ |
| **1** | 4 | $0 + 4$ | **4** | Items $[4, 5, 6, 7]$ |
| **2** | 3 | $4 + 4$ | **8** | Items $[8, 9, 10]$ |
| **3** | 3 | $8 + 3$ | **11** | Items $[11, 12, 13]$ |

- *Check:* Final index is $11 + 3 - 1 = 13$ (Total 14 elements, indices $[0 \dots 13]$).

## 11. Conceptual Questions & Answers (Exam & Viva Focus)

### Q1: What should non-root processes pass for `sendbuf` in `MPI_Scatter`?
**Answer:** On all non-root processes (`rank != root`), the `sendbuf`, `sendcount`, and `sendtype` parameters are completely ignored by the MPI library. Non-root ranks should pass `NULL` for `sendbuf`, `0` for `sendcount`, and `MPI_DATATYPE_NULL` (or any valid datatype) for `sendtype`.

### Q2: Why does `MPI_Scatter` require both `sendcount` and `recvcount` if they are usually equal?
**Answer:** While `sendcount` and `recvcount` must match in number of transmitted elements, passing both allows the sender and receiver to specify **different derived datatypes**. For example, the sender could send $1$ contiguous block of 100 elements using a derived struct type (`sendcount = 1`), while the receiver receives them as $100$ individual `MPI_DOUBLE`s (`recvcount = 100`).

### Q3: When should `MPI_Scatter` be chosen over `MPI_Bcast`?
**Answer:** `MPI_Scatter` must be chosen whenever processes need to operate on **independent sub-domains** of a problem (data parallelism) and storing the entire dataset on every node would exceed memory limits or cause redundant computation. `MPI_Bcast` is chosen only when every process genuinely needs an identical copy of the exact same data (e.g., global configuration constants, lookup tables).

## 12. Quick Revision Sheet

- **Core Function:** `MPI_Scatter(sendbuf, sendcount, sendtype, recvbuf, recvcount, recvtype, root, comm)`.
- **The Golden Rule:** `sendcount` is elements sent **per process**, NOT total elements!
- **Data Pattern:** One-to-All personalized partitioning.
- **Uneven Domains:** Use `MPI_Scatterv` with `sendcounts[]` and displacement offsets `displs[]`.
- **Memory Optimization:** Pass `MPI_IN_PLACE` as `recvbuf` on the root rank to avoid duplicating root's slice.
- **Invariants:** Every rank in communicator must call `MPI_Scatter`; root must match across all calls.
